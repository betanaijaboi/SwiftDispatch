# Database Design / Entity Relationship Diagram (ERD)
## SwiftDispatch

**Database:** MongoDB (NoSQL / Document Store)  
**ODM:** Mongoose  
**Note:** MongoDB uses embedded documents and references instead of strict foreign keys. Relationships below show the reference pattern used.

---

## Collections Overview

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│    users     │     │   orders    │     │  locations  │
│  (customers  │◄────│             │────►│  (embedded) │

└─────────────┘     └─────────────┘
```

## Collection 1: `users`

Stores both customers and riders in a single collection, differentiated by `role`.

```
users
├── _id              ObjectId    PK — auto-generated by MongoDB
├── name             String      Required. Full name.
├── email            String      Required. Unique. Lowercase.
├── phone            String      Required.
├── password         String      Required. bcrypt hashed.
├── role             String      Enum: ['customer', 'rider']
├── avatar           String      Optional. URL to profile image.
├── isVerified       Boolean     Default: false. True after admin verification.
├── rating           Number      Average rating. Default: 5.0.
├── totalRides       Number      Lifetime completed deliveries. Default: 0.
├── createdAt        Date        Auto. Timestamp of registration.
├── updatedAt        Date        Auto. Last modification timestamp.
│
│   ── Rider-only fields (present when role === 'rider') ──
├── vehicleType      String      Enum: ['bike', 'bicycle', 'car', 'van']
├── vehiclePlate     String      Plate number. Uppercase.
├── vehicleColor     String      Optional.
├── isOnline         Boolean     Default: false. Rider availability toggle.
├── currentLocation  Object      Embedded. Last known GPS coordinates.
│   ├── latitude     Number
│   └── longitude    Number
├── earnings         Number      Total lifetime earnings in ₦. Default: 0.
└── completedDeliveries Number  Default: 0.
```

**Indexes:**
- `email` — unique index
- `role` — for filtering riders vs customers
- `isOnline` — for querying available riders

---

## Collection 2: `orders`

Central collection tracking the full lifecycle of every delivery request.

```
orders
├── _id              ObjectId    PK — auto-generated
├── customerId       ObjectId    FK → users._id (role: customer)
├── riderId          ObjectId    FK → users._id (role: rider). Null until accepted.
│
├── pickup           Object      Embedded pickup location.
│   ├── address      String      Human-readable address.
│   ├── latitude     Number
│   └── longitude    Number
│
├── dropoff          Object      Embedded drop-off location.
│   ├── address      String
│   ├── latitude     Number
│   └── longitude    Number
│
├── vehicleType      String      Enum: ['bike', 'bicycle', 'car', 'van']
├── status           String      Enum (see Order Status below).
├── price            Number      Total order price in ₦.
├── distance         Number      Calculated distance in km.
├── estimatedTime    Number      ETA in minutes.
├── note             String      Optional. Customer note to rider.
├── packageDescription String   Optional. What is being delivered.
├── paymentMethod    String      Enum: ['cash', 'card', 'wallet']
├── paymentStatus    String      Enum: ['pending', 'completed', 'failed']
│
├── rating           Number      1–5 stars. Set after delivery.
├── review           String      Optional text review.
│
├── createdAt        Date        Auto. When order was placed.
├── acceptedAt       Date        When rider accepted.
├── pickedUpAt       Date        When rider collected package.
├── deliveredAt      Date        When delivery was completed.
└── cancelledAt      Date        If cancelled, when.
```

**Order Status Enum (lifecycle):**
```
pending
  → searching       (system is looking for a rider)
  → accepted        (rider accepted the order)
  → pickup          (rider arrived at pickup location)
  → in_transit      (package collected, en route to drop-off)
  → delivered       (delivery completed)
  → cancelled       (cancelled by customer or system)
  → rated           (customer submitted rating)
```

**Indexes:**
- `customerId` — to fetch a customer's orders
- `riderId` — to fetch a rider's orders
- `status` — for filtering active vs completed orders
- `createdAt` — for date-range queries

## Collection 3: `notifications` (Phase 2)

```
notifications
├── _id              ObjectId    PK
├── userId           ObjectId    FK → users._id
├── title            String      Notification heading.
├── message          String      Full notification body.
├── type             String      Enum: ['order', 'promo', 'system']
├── read             Boolean     Default: false.
├── orderId          ObjectId    FK → orders._id. Optional.
└── createdAt        Date        Auto.
```

---

## Collection 4: `messages` (Phase 2 — In-trip chat)

```
messages
├── _id              ObjectId    PK
├── orderId          ObjectId    FK → orders._id
├── senderId         ObjectId    FK → users._id
├── senderRole       String      Enum: ['customer', 'rider']
├── message          String      Message content.
└── createdAt        Date        Auto.
```

## Relationships Summary

```
┌──────────────────────────────────────────────────────────────────┐
│  users (1) ───────────────────── (many) orders  [as customer]   │
│  users (1) ───────────────────── (many) orders  [as rider]      │
│  orders (1) ──────────────────── (many) messages               │
│  users (1) ───────────────────── (many) messages               │
│  users (1) ───────────────────── (many) notifications          │
│  orders (1) ──────────────────── (1) rating     [embedded]     │
│  orders (1) ──────────────────── (1) pickup     [embedded]     │
│  orders (1) ──────────────────── (1) dropoff    [embedded]     │
└──────────────────────────────────────────────────────────────────┘
```
